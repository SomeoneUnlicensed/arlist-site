Arlist ID — обзор

Arlist ID — это единая система входа («Войти с Arlist ID») на базе протокола OpenID Connect (OAuth 2.0). Partner-сервисы (например, leetcot.ru) подключают её как стандартного OIDC-провайдера — через библиотеки типа Auth.js / NextAuth, oidc-client и им подобные.

Issuer: https://arlist.ru
Discovery document: https://arlist.ru/.well-known/openid-configuration

Discovery-документ всегда содержит актуальные адреса всех endpoint'ов — рекомендуем настраивать клиентов через issuer, а не хардкодить пути вручную.

Endpoints

EndpointПуть
Authorization/auth
Token/token
Userinfo/me
JWKS/jwks
End session/session/end

Все пути — относительно https://arlist.ru.

Authorization Code Flow + PKCE

Arlist ID поддерживает только response_type=code с обязательным PKCE (S256). Implicit-флоу без code не рекомендуется.

1. Редирект пользователя на authorization endpoint

GET https://arlist.ru/auth
  ?client_id=<ваш client_id>
  &response_type=code
  &redirect_uri=https://ваш-сервис.ru/callback
  &scope=openid email profile
  &code_challenge=<BASE64URL(SHA256(code_verifier))>
  &code_challenge_method=S256
  &state=<random-string>

Пользователь проходит логин на arlist.ru и (при первом входе) подтверждает запрашиваемые scope. После этого браузер редиректится на ваш redirect_uri:

https://ваш-сервис.ru/callback?code=AbC123...&state=<тот же state>&iss=https://arlist.ru

2. Обмен code на токены (server-to-server)

# Authorization: Basic base64(client_id:client_secret)
POST https://arlist.ru/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=AbC123...
&redirect_uri=https://ваш-сервис.ru/callback
&code_verifier=<исходный code_verifier>

Ответ:

{
  "access_token": "...",
  "id_token": "eyJhbGciOiJSUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "openid email profile"
}

3. Получение профиля пользователя

GET https://arlist.ru/me
Authorization: Bearer <access_token>
{
  "sub": "cuid...",
  "email": "user@example.com",
  "name": "Имя Пользователя"
}

Scopes и claims

ScopeClaimsДоступ
openidsubлюбой клиент
emailemailлюбой клиент
profilenameлюбой клиент
internalrole, isVerifiedтолько доверенные внутренние клиенты (isTrusted)

Scope internal предоставляется только клиентам, помеченным как доверенные (isTrusted = true) в реестре OAuth-клиентов Arlist — он не выдаётся сторонним партнёрам.

Пример подключения (Auth.js / NextAuth)

// auth.config.ts
{
  id: "arlist",
  name: "Arlist ID",
  type: "oidc",
  issuer: "https://arlist.ru",
  clientId: process.env.ARLIST_CLIENT_ID,
  clientSecret: process.env.ARLIST_CLIENT_SECRET,
  authorization: { params: { scope: "openid email profile" } },
}

Auth.js сам подтянет все endpoint'ы из discovery-документа и сделает PKCE автоматически — никакой ручной сборки URL не требуется.

Важно: не конструируйте вручную редирект-ссылки вида /auth/<uid> — это внутренний служебный маршрут oidc-провайдера ("resume"), используемый только самим сервером Arlist после завершения логина. Партнёрским сервисам нужно работать исключительно с /auth (authorization endpoint) и redirect_uri, на который вернётся браузер.

Arlist API — обзор

Серверный (server-to-server) REST API для партнёрских сервисов — позволяет получить публичные данные пользователя Arlist по его id или email, без прохождения OAuth-флоу со стороны конечного пользователя.

Base URL: https://arlist.ru/api/v1

Аутентификация

Все запросы к Arlist API требуют HTTP Basic Auth с вашими серверными учётными данными клиента: 

Authorization: Basic base64(client_id:client_secret)

Это те же client_id / client_secret, что выданы вам для OIDC-интеграции — отдельных ключей заводить не нужно. Передавайте их только с сервера, никогда из браузера или мобильного клиента.

GET/users/:id

Возвращает публичные данные пользователя по его внутреннему ID.

GET /api/v1/users/cuid123abc
Authorization: Basic ...

Ответ 200 OK:

{
  "id": "cuid123abc",
  "email": "user@example.com",
  "name": "Имя Пользователя",
  "role": "USER",
  "isVerified": true,
  "isBanned": false,
  "createdAt": "2026-01-15T10:00:00.000Z"
}

Если запрос выполнен доверенным (isTrusted) клиентом, в ответе дополнительно присутствует поле balanceKopecks — баланс пользователя в копейках.

GET/users/by-email/:email

То же самое, но поиск по email вместо ID.

GET /api/v1/users/by-email/user%40example.com
Authorization: Basic ...

Формат ответа идентичен /users/:id.

Ошибки

КодКогда возникает
401Отсутствует/неверный заголовок Authorization, либо неверные client_id/client_secret
404Пользователь с таким id или email не найден
500Внутренняя ошибка сервера

Тело ошибки всегда в формате { "error": "..." }.
